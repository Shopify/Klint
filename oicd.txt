All NPM Classic tokens were permanently deprecated December 9th, 2025. Please use OIDC (Trusted Publishing) when publishing public npm packages at Shopify going forward.

For detailed setup instructions and configuration options, see npm's Trusted Publishers documentation.

Prerequisites
 GitHub-hosted runners (OIDC doesn't work with self-hosted runners)
 Access to update GitHub Actions workflows in your repository

Before OIDC can be configured, your package must exist on npmjs.com. Publish your first version using a token:

Create a token:

Add it to GitHub secrets as NPM_TOKEN

For Changesets
name: Release
on:
  push:
    branches:
      - main

permissions:
  contents: write       # Required for Changesets to push branches
  id-token: write       # Required for OIDC authentication
  pull-requests: write  # Required for Changesets to create PRs

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: '20'  # Must be 20+ for npm 11.5.1+
          registry-url: 'https://registry.npmjs.org'
          cache: yarn

      - name: Update npm to latest
        run: npm install -g npm@latest

      - name: Install dependencies
        run: yarn install

      - name: Create Release Pull Request or Publish
        uses: changesets/action@v1
        with:
          publish: yarn release
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          NPM_TOKEN: ''  # Empty string forces OIDC

Key changes:

Add permissions: id-token: write
Ensure Node is 20+ and npm is latest
Change NPM_TOKEN to empty string '' (not removed - literally empty string)
Use changesets/action@v1 (not an old SHA)

Troubleshooting
Error: "EOTP - This operation requires a one-time password"
Cause: npm is trying to use token auth instead of OIDC

Fix: Check that NPM_TOKEN is set to empty string (not removed):

env:
  NPM_TOKEN: ''  # Literally empty string

Workflow Updated But Nothing Published (Changesets)
Cause: Changesets only publishes when there's a version bump

Fix: Create a changeset:

npx changeset

Error: "package not found" (404) - For Reusable Workflows Only
⚠️ This only applies if you're using workflow_call (reusable workflows). Most developers won't encounter this.

Symptom:

npm verbose oidc Failed token exchange request with body message: OIDC token exchange error - package not found

Root cause: With workflow_call, npm looks for the CALLER workflow in your Trusted Publisher config, not the reusable workflow. If multiple workflows call your reusable workflow, you hit the "one Trusted Publisher per package" limit again.

Solution: Switch to workflow_dispatch ✅ Tested successfully Oct 28, 2025

Change your workflow trigger:

on:
  workflow_dispatch:  # Changed from workflow_call
    inputs:
      release_type:
        required: true
        type: choice
        options: [snapshot, release, tag]

permissions:
  id-token: write  # Required for OIDC

Then configure this workflow as your Trusted Publisher on npmjs.com. Other workflows can trigger it via the GitHub API or manually.

Reference: See Tunca's successful implementation with @shopify/shop-minis-platform packages.

Note: npm dist-tag behavior with OIDC is still being validated. If you need dist-tag, keep it in the same workflow as your publish step or reach out in #help-eng-infrastructure.
